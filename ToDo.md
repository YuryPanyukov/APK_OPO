## 🔴 Известные замечания (баги / недочёты)

- [ ] **Файлы фото не удаляются с диска при удалении комиссии** —
      `DeleteCommissionUseCase` удаляет только строку комиссии (каскад в БД
      убирает замечания и фото-записи), но сами файлы изображений остаются
      в `files/pictures/photos`. Нужна очистка по образцу `DeleteRemarkUseCase`
      (сбор путей фото → удаление строк → удаление файлов через `PhotoFiles`).
- [ ] **UI-тестов нет для `RemarkDetailScreen`** — экран принимает ViewModel,
      зависящий от Room/`AppContainer`; для покрытия нужен рефакторинг
      на stateless-контент с параметрами (как сделано для остальных экранов).
- [ ] **Возможная гонка в `AddRemarkViewModel` (режим правки)** — `loadJob?.join()`
      защищает от затирания ввода при сохранении, но если пользователь начнёт
      вводить текст до завершения загрузки, загрузка перезапишет поля.
      Решение: применять предзаполнение только к ещё не изменённым полям.
- [ ] **Нет обработки «GPS недоступен»** — `LocationProvider.currentPoint()`
      может вернуть `null` молча; в форме координаты просто не появляются.
      Хорошо бы показывать понятное сообщение («Сигнал GPS не получен»).
- [ ] **Фото сохраняются в полном размере** — копия из галереи/камеры кладётся
      в хранилище без сжатия; на длинных осмотрах быстро занимает память.
      Идея: ресайз/сжатие (например, до 2000 px, JPEG q=85) при сохранении.
- [ ] **Тексты интерфейса захардкожены в коде** — `strings.xml` содержит только
      `app_name`. Для локализации и корректного доступibility все строки
      стоит вынести в ресурсы.
- [ ] **Схема БД без миграций** — при изменении Entity нужен явный миграционный
      план (сейчас schema version = 1). Продумать migration-политику до того,
      как изменение схемы понадобится (destructive fallback допустим только
      в dev).
